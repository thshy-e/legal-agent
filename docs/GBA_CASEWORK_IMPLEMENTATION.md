# 大湾区案件协同交付说明

更新：2026-10-25。适用版本：`gba-2026-10-25-v1`。本文件描述实际实现及验证边界，不能替代正式法律审查。

## 已实现

- 保留 FastAPI、LangGraph、现有页面和聊天接口，新增“案件协同”入口。普通精确法条问答使用独立轻量路径。
- LangGraph 依次执行接待、QA 法源检索、Judge 请求分析、确定性计算、独立 Review、用户确认、Doc 文书计划和文书一致性审查。QA、Judge、Doc、Risk 的相关能力接入同一案件状态。
- 事实来源、持有声明、法律主张、条件测算分开保存。“用户称违法解除”不成为违法认定，“没有考勤”不成为持有证据。
- 普通分析与案件协同共用材料陈述提取；提及、询问、假设及单位持有不自动记为用户持有。逐项合并材料并保存来源，冲突持久保存，重试或重载不能消除关键矛盾；须明确澄清后才能确认。
- 协商一致、第38条具体事由及告知、第40条类别、第41条实体与程序条件、继续履行救济分别记录。前端按解除类型显示相关条件，逐项标“用户陈述，待举证”；不适用的 N/2N 备选没有计算金额。
- 金额使用 Decimal；补偿工资与代通知金工资分开。N、2N 作为备选，2N 与代通知金不能累计；第四十一条不自动附加代通知金。欠薪只核算逐期应付减实付，不自动加处罚性金额。
- 事实、地域、日期或知识版本改变后，分析、金额、确认和文书失效。确认必须携带当前 `expected_case_version`，过期返回 409；用户确认不表示证据真实性已核验。
- 文书金额直接引用计算对象，主体信息缺失保留占位，证据目录只列用户称持有的材料，输出可复制 Markdown。文书审查最多自动修订一次，仍有关键问题则阻止草稿交付。
- SSE 节点事件在实际执行时发送；检索、模型或审查失败保留阶段产物和原因。结构化模型输出最多纠正一次。损坏的 JSON 会话存储保留原文件并返回 503。
- 前端增加事实修订、地域覆盖、期间工资、材料持有、请求选择、版本确认、进度及官方原文查看。移除固定胜诉率、风险分数和证据强度分数。

## 知识库实况

清单唯一入口为 `data/legal_sources/manifest.json`；网页快照在 `snapshots/`。当前收录 12 份法规版本、2 份办事指引和 18 个逐案参考记录，构建 748 条检索记录；另有 6 个地域参数记录，其中 4 个最低工资版本已核验、2 个经济补偿封顶参数明确为 pending。

全国层包含劳动法、劳动合同法、实施条例、仲裁法、劳动争议司法解释（一）（二）及工资支付暂行规定；省级包含广东工资支付条例及劳动人事争议处理办法新旧版本；城市层包含深圳工资支付条例新旧版本、广深指引及最低工资参数。条款保存原文、官方链接、版本、地域、效力期间和核验日期；摘要另存。

地域与日期先过滤，再精确法名条号匹配或词项检索。可选向量检索与词项排序做融合，也只能排序已满足地域、时间条件的文档。无密钥版本使用词项检索；专用工作空间原生接口已完成748条1024维向量构建，并通过8项精确法名、城市和时间边界检查；尚未测量语义检索准确率，默认仍为词项模式。

案例为广州法院 6 个典型案例、广州司法局 1 个法律援助报道、深圳人社 5 个拒不支付劳动报酬刑事典型案例及新增 6 份深圳普通仲裁裁决记录。新增裁决包含欠薪与解除获支持、解除获认可、调薪举证不足等方向，保留案号、发布日期、裁决日期、原文及历史适用限制；不宣称它们是 18 份生效法院判决。Judge/Review 可以读取案例处理要点和限制，深圳检索优先采用普通仲裁参考，避免刑事欠薪报道主导普通欠薪分析。案例摘录与官方快照逐条核对并校验哈希。

深圳一则刑事报道存在刑拘与判决日期矛盾，已标注，不作为日期事实依据。2017 年案号的严重失职解除反例，实际落款裁决日为 2018-01-09，网页发布日为 2020-09-28，三者分别保存；2022 年社保解除个案的历史处理不能机械移用于司法解释（二）实施后的新案。旧 `data/case/cases.txt` 是未核验教学资料，不进入新清单。

深圳工资条例按 2025-12-05 切换版本，以实际施行日而非 2026 公报网页日期判断。司法解释（一）第三十二条第一款自 2025-09-01 废止：保留历史全文，现行检索仅返回未废止的第二款。劳动法第八十二条的旧“60日”文字不作为现行一般仲裁时效结论，精确查该条时同时说明仲裁法第二十七条及其例外。

广州、深圳为重点覆盖；另外七市显示“已覆盖全国及广东规则，城市专项资料待完善”，不借用广深参数。实际港澳或跨境履行停止内地自动计算，香港身份、港资股东标签本身不自动触发。

## 启动与构建

```powershell
# 使用项目现有环境；无需密钥即可走规则、检索及欠薪草稿流程
.\venv\Scripts\python.exe build_db.py --activate
$env:CASE_MODEL_ENABLED="0"
.\venv\Scripts\python.exe start_server.py
```

默认地址 `http://localhost:8000`。本次浏览器验收使用 `http://127.0.0.1:18080`。

```powershell
# 刷新网页仅下载快照，不自动激活；必须检查差异与效力信息
.\venv\Scripts\python.exe scripts/collect_official_sources.py
.\venv\Scripts\python.exe scripts/prepare_legal_manifest.py
.\venv\Scripts\python.exe build_db.py
.\venv\Scripts\python.exe build_db.py --activate
# 回到上一个清单索引；旧 Chroma 目录不被覆盖
.\venv\Scripts\python.exe build_db.py --rollback
```

两个构建入口 `build_db.py` 与 `python -m legal_ai_agent.rag.build_db` 调用同一构建器。候选库独立构建、核验快照哈希及条数后原子切换指针。切换后重启后端；已有案件会因知识摘要变化要求重新分析和确认。`--init/--force` 旧参数已移除。

`.env` 可配置 `DASHSCOPE_API_KEY`、`CASE_MODEL_ENABLED=1`。Judge/Doc固定 `qwen-plus`，Review支持独立配置 `CASE_REVIEW_MODEL=qwen3.8-max`；temperature 0.1，记录实际返回模型信息、usage 与耗时；无密钥时明确标注规则模式，不宣称已执行真实模型协作。启用可选混合检索须先执行 `build_db.py --embeddings --activate`，再设置 `LEGAL_VECTOR_SEARCH=1`。本地私有会话、API 密钥、构建索引不入库。

当前验证结果与运行环境见 `evaluation/casework_v2/validation.json`；逐案结果、失败和原始版本对照单独保存。浏览器已验证欠薪确认草稿及修改事实后的再次确认。

工程测试覆盖日期/地域隔离、精确法名、部分废止、否定表达、工资口径、缺参、互斥、版本确认、存储重载、失败、模型结构化重试及文书审查上限。少数补偿算术测试使用名称明确的 `SYNTHETIC_TEST_CAP`，仅用于验证公式，不会写入运行库。

冻结集 `data/evaluation/case_tasks_v2.json` 共 60 案：解除 20、欠薪 10、地域版本 10、多轮修正 10、否定缺失 10，附 SHA256。v1 原文件保留不变；v2 仅纠正 W05/W06/W07 的零欠付余额预期：仍核算 0.00 元，但不再允许确认“追讨零元”草稿。全部案件输入、分组和金额预期保持不变，变更写入 changes_from_previous。v1 旧预期在新行为下为 57/60，另存历史报告；v2 为当前工程契约。两版均是**公开工程验证集**，不是盲测集。

模型消融脚本在同一模型、法源、工具输出和采样条件下比较 single_agent、collaboration_no_review、collaboration_review，分别执行 1/2/3 次角色调用，记录实际调用数、输出、token 和耗时。白名单只提供用户输入、事实、候选请求、法源及计算对象，**不把预期答案、评分标签、生产 Judge 分析或生产 Review 结论提供给模型**。续跑必须同时匹配数据、知识、实验协议代码摘要及模型配置；失败调用也记录耗时，不伪造 token。

该脚本是共享工具结果的结构化决策对照，不代表生产工作流的完整吞吐或端到端用户效果。工作空间接口已完成180组结构化输出、360次成功调用；单Agent/协同无审查/协同有审查分别15/2/8组有自动标记。增加审查未在该指标上改善表现，不能据此声称法律准确率或稳定收益，详见 `evaluation/casework_v2/MEASURED_MODEL_RESULTS.md`。三组最终输出统一使用JSON模式、90秒超时，最多6组独立任务并发；初始40秒超时及未约束格式试跑另存目录，公共接口401记录亦保留。续跑同时校验数据、知识、协议、采样及Base URL，401/403仍会保存后停止后续请求。教师/律师评分留空，未标“专家审核”。人工复核表见 `evaluation/casework_v1/LEGAL_REVIEW_RUBRIC.md`，待核验问题及官方出处见 `evaluation/casework_v2/LEGAL_REVIEW_PACKET.md`。

`scripts/legal_review.py` 提供复核包导出、UTF-8 CSV及校验汇总，绑定原数据集和评测报告哈希，去掉开发预期答案；未运行/失败模型输出单列。当前已导出60份规则工程产物和180份真实模型产物，评分全部待审；八维度分数按适用项统计，严重错误另计，不自动转为法律准确率或专家审核。操作见 `evaluation/casework_v2/LEGAL_REVIEW_WORKFLOW.md`。

## 未完成且不可对外声称的能力

1. **广深经济补偿封顶参数口径尚待核验。** 官方年平均工资统计存在不同口径，不能直接指定为第四十七条适用参数。当前 N/2N 保留公式并阻止确认；代通知金可分别测算，但全案存在关键缺失时仍不能确认生成草稿。欠薪流程可完整运行。补齐参数须记录市、适用期间、数值、统计口径、用途、官方依据并设为 verified，然后重建索引、重新确认案件。
2. 历史法源覆盖以清单列出的版本起日为边界，不能宣称所有历史劳动争议均支持。2008 年前工龄、特殊用工、跨市适用未澄清、港澳跨境等交专业复核。
3. 官方指引快照不等于每个区仲裁窗口当天材料要求；提交前重新核实。广东与深圳离职工资结清期限差异显式提示专业核验，未机械设地方优先。
4. 真实模型三组实验及embedding联网已完成；模型角色曾过度拦截草稿、丢弃确认引用，失败记录保留。办案链路和复杂语言仍需持续复测，独立盲测及教师/律师复审尚未完成；工程通过率不等于法律适用准确率。
5. JSON + RLock 是单进程演示实现，整个案件事务加锁；并发多进程/多实例部署需事务数据库。没有 OCR、证据真伪鉴定、自动提交仲裁。

## 截止前优先级

先核定广深第四十七条参数口径、解除成立条件及争议规则，并安排法学教师/律师复审。随后运行真实 Qwen 对照及人工逐案评分，另征集未参与开发的盲测案件。最后冻结数据、代码、运行环境、报告和演示视频。技术报告初稿见 `COMPETITION_TECHNICAL_REPORT.md`。申报材料区分“已实现”“工程已验证”“待法律复核”，不填未经测量的胜诉率或协同提升百分比。

## 项目介绍

劳法智枢是面向劳动者和法律援助人员的劳动争议辅助系统。项目以全国基础法源、广东规则和广深城市资料为依据，通过多角色协同完成事实澄清、法源检索、分请求分析、确定性计算和交叉审查，在用户确认后形成金额可复核、依据可追溯、材料相互一致的维权准备草稿。
