# 案件角色的输入、权限与验收边界

当前生产工作流版本：casework-20261026-v16；自然咨询：conversation-20261026-v16。这里描述已实现的角色输入，具体实测范围见验收记录。模型输入数据、上一角色意见和用户确认均不能改变法源原文、确定性金额或事实真实性状态。

| 角色 | 读取内容 | 可写产物 | 禁止改变 |
| --- | --- | --- | --- |
| 接待 | 本轮输入、该会话既有事实和冲突 | 有来源的事实补充、缺失项、修订 | 将否定、假设、询问当事实；将用户法律标签当认定 |
| QA 检索 | 履行地、单位所在地、日期、当前业务 | 按地域时间筛选的法条、指引和案例 | 借用他市参数，机械用地方规则覆盖全国规则 |
| Judge | 当前请求相关事实及法源；参考案例同时附限制 | 每请求支持材料、不利因素、引用和追问 | 自行计算、补造事实、裁定违法已经成立 |
| 计算工具 | 已建模条件、日期、工资期间及参数版本 | Decimal金额、公式、假设、缺失参数 | 从生成文字重新提取金额，填入未经核验参数 |
| Review | 原始陈述及来源、请求、工具计算、法条、Judge引用编号 | 分类问题和引用；事实字段与法源编号分别保存 | 删除规则检查结果、改金额或用证据缺失证明事实不存在 |
| Doc | 当前版本确认、固定请求金额引用、声明持有的材料 | 结构化文书计划，经校验后确定性Markdown | 改金额、遗漏确认引用、把缺失考勤列为持有证据 |

Review不读取Judge的支持/不利意见和案例裁判结论，避免把参考案件的举证情况直接套在本案。Judge仍能使用案例，前端仍展示原始来源。欠薪单一请求的上下文排除无关的补偿工资基数和解除法条；劳动履行及工资约定陈述保留，并进入文书事实段。所有陈述仍标记为未经证据真伪核验。

Review输出的source_ids仅允许法源编号，fact_fields用于事实路径。编号枚举进入提示中的JSON Schema，返回后仍执行本地校验；接口使用json_object，不宣称服务端已强制执行完整Schema。错误输出最多纠正一次，调用记录保存每次实际提示的哈希、字符数、模型返回、用量及耗时；超时不以无限重试掩盖。

v8要求关键法律问题同时提供law_excerpts中的连续原文及fact_excerpts中的实际输入/工具值，真正空缺的事实使用missing_fact_fields。后端逐项核对本轮来源、原文片段、字段路径和原值；fact_fields由引用位置合并生成，避免同一依赖重复手填。事实冲突至少指出两个不同的原始片段。新增工资支付周期、约定支付日及劳动关系建立条文后再审查，不能从记忆补造地方规定。

片段验证只证明引用来自本轮输入，不证明两段文字之间存在法律上的推理关系。引用错误、超限或未知字段会在最多一次纠正后阻断流程，不静默删掉问题；引用通过后的critical仍阻断。前端可展开查看每个审查问题的原始片段及官方链接。Judge和Doc采用qwen-plus、temperature=0.1、timeout=60、max_retries=0、max_tokens=2400及json_object；Review可独立选择qwen3.8-max，使用low推理档、90秒及4096输出上限，其他边界保持。默认配置仍为qwen-plus，不改变已完成的公平对照实验。v7的1600上限截断记录保留。

v10将当前在职状态保存为有来源、待举证的枚举，并给Review提供确定性日期比较；不让模型重新凭文字猜测日期先后。日期工具不裁定时效或请求成立。v11将角色模型配置和启用状态摘要纳入依赖，切换配置会撤销旧确认和文书。

v12允许同时记录8个缺失主体字段，missing_fact_fields上限12，逐项空值校验不变。v13将not_selected备选保留在案件和页面的排除说明中，不再要求Judge逐项分析。required_claim_ids及输出Schema明确当前请求编号、条数和引用；遗漏仍最多纠正一次，并报告具体缺少的编号。全部请求已排除时Judge/Review不调用模型，仍保留规则关键问题。模型调用新增finish_reason记录，不将提前终止计为真实协同。

规则发现的关键缺条件、金额/版本错误不能被模型放行。模型提出的关键问题也会阻止确认；当前没有自动语义裁定器来区分所有误报，不能随意将legal_condition降为警告来制造通过。evidence_gap及subject_placeholder适用辅助草稿政策，保留模型原级别和处理说明。

v14新增一次引用分析修订：仅当没有缺失项、失败或既有规则关键问题，且本轮所有关键发现均来自实际Review输出、类别为citation并涉及Judge已引用法源时，将这些发现交回Judge。Judge须重读本轮法源，只重写分析；运行前后比较事实、来源、请求、金额、依赖、确认及文书，越权改动会恢复并阻断。修订后重新独立调用Review，不向其传递先前反馈或结论。复审仍有关键问题或模型失败则停止，不进入第二次分析修订。初审问题不会自动降级或删除，保存在analysis_review_history；当前有效问题由保留的规则问题和本次复审共同组成。结构化JSON纠正一次与业务分析修订一次是不同上限，均记录实际调用。

analysis_repair记录本轮修订次数、反馈及结果，每次请求重新置零；历史审查保留最近20次记录，含案件版本、事实摘要、分析、原始模型审查、问题及来源链接。历史记录不回灌新请求。确认仍由原条件与版本闸门决定，复审通过不表示请求已获法律认定。

v15保持必填字段、原文锚点及两次尝试上限，格式纠正改为返回具体字段路径、错误类型和短说明，不回传校验异常中的整段案件输入。Review提示明确没有法条引用也必须输出source_ids空数组，事实冲突仍须两个不同原始片段；未补全继续阻断，不由程序代填。达到length结束原因的输出，即使JSON可解析也算失败。SDK在构造模型消息之前抛出截断异常时，从异常携带的completion读取实际模型、结束原因、内容片段和用量，metadata_source标为sdk_exception_completion；失败不会因此改为成功。只有接口实际报告了完整计数才生成标准usage；缺失或部分用量保存为未知及可用的raw_usage，不推定为零成本，不用请求模型名冒充实际模型名。日志截取内容时另记output_log_truncated，区别于模型输出截断。

固定合成输入见data/evaluation/live_workflow_fixture_v1.json，配套SHA256；脚本拒绝覆盖已有报告。v5至v8及v10全Plus各连续三次未完成闭环；v11混合配置连续3/3完成相同四阶段，另两个真实反例保持关键阻断。所有原始输出和实现哈希保留，详见[evaluation/casework_v2/LIVE_WORKFLOW_FINDINGS.md](evaluation/casework_v2/LIVE_WORKFLOW_FINDINGS.md)。这不改变此前全Plus对照实验，也不证明广泛法律准确率。

下一步需要基于这些失败样本，人工明确“尚未陈述”“待举证”“可选请求不完整”的判定表，再验证审查引用与法条具体命题是否对应；同时加入真实缺条件及事实冲突的反例。保持冻结输入和固定重复次数，公开全部结果；单一案例重复不替代独立盲测、法律准确率或专家复核。

## v16自然咨询上下文

普通问答不再维护独立Agent记忆；服务端按session_id读取最近六轮实际问答（总长度上限12000字符），旧摘要明确标记。独立的一般问题不附带旧案工资和金额；显式案件解释可读取只读快照，不能修改或确认事实。模型只输出回答和实际检索来源编号，确定性规则控制案件操作。解释失败保留有效案件状态；明确、唯一工资期间的修订才进入已有失效和重算流程。
