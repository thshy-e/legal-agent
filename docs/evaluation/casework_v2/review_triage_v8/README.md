# 审查中间产物复核包（尚无人工评分）

packet.json保存v8固定合成案例三次真实复测的六次Review调用，包括原始JSON、生产校验结果、原始事实、计算对象和法源。packet.sha256校验包内容；各原始运行报告哈希也在包内。输入不是独立盲测，模型意见不是专家意见。

这些是失败流程中的审查中间产物，不是六份可交付法律答案，不并入原180份三组实验，也不计作人工法律准确率。JSON可解析不等于生产结构或引用校验通过；最后一次Review校验通过也没有使该案通过，因为仍有critical问题。

人工逐项核查时请特别记录：

- 用户已经陈述“目前仍在该单位工作”时，空end_date是否仍是本次欠薪本金草稿的关键事实缺失；不得将“尚未核验”与“尚未陈述”混为一谈。
- 原文确实要求按约定日期支付，但是否支持模型额外提出的支付日、精度及仲裁时效结论；不要只核对出现了同一个法条编号。
- 全国支付义务与地方支付条款的关系；未列尽所有相关条文是否必然属于阻止草稿的引用错误。
- 考勤缺失、合同原件未验真、主体信息占位分别应如何提示；哪些场景确实应阻止确认。
- 对本次属于无争议陈述前提的计算，哪些原始事实片段与法条命题真正支持所列问题；同样检查真实冲突或关键缺事实的反例，避免仅降低误报而放过实质错误。

每次调用的human_review字段均为空。复核人需真实填写身份、日期、分类、理由和来源；分歧应保留。当前包没有伪造教师或律师意见，不自动生成“专家审核”标签。参考[人工复核规则](../../casework_v1/LEGAL_REVIEW_RUBRIC.md)。
